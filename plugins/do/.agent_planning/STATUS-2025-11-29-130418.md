## Current Architecture Assessment

### How Slash Commands Invoke Subagents

**File**: `plugins/dev-loop/commands/evaluate-and-plan.md`
```markdown
Step 1: Use the dev-loop:project-evaluator agent to evaluate the current status of the project.

Step 2: Only after project-evaluator has completed, use the dev-loop:status-planner agent
to plan the remaining work for the project based on the output of Step 1.
```

**Mechanism**: Commands are markdown files that expand into prompts. The prompts instruct Claude to invoke agents sequentially using agent names (e.g., "dev-loop:project-evaluator").

**Invocation Flow**:
1. User runs `/dev-loop:evaluate-and-plan`
2. Command expands to prompt text
3. Prompt instructs Claude to "Use the dev-loop:project-evaluator agent"
4. Claude spawns subagent with isolated context
5. Subagent completes work, produces final summary
6. **Summary is returned to parent context but NOT displayed to user**
7. Process repeats for next agent (status-planner)

### What Happens to Subagent Output

**Current Behavior** (based on Claude Code documentation):

1. **Default Visibility**: Subagent internals are obscured from users
   - Users see that a subagent was invoked (agent ID displayed)
   - Users can approve tool usage (file reads/writes)
   - Users CANNOT see subagent thinking, summaries, or completion status

2. **Access Method**: Users can press `ctrl-o` to expand message history and view:
   - Subagent prompt
   - Subagent summary results
   - Complete subagent context

3. **Return Value**: Subagents return "concise resulting context" to parent conversation
   - This includes the final summary
   - Parent agent receives the summary
   - User does NOT see the summary (unless ctrl-o)

**Problem**: The "Final Summary (Required)" sections in all 7 agents produce valuable output that users need to see, but it's buried in hidden context.

## Solution Evaluation

### Solution 1: File-Based Summary Output (RECOMMENDED)

**Approach**: Each agent writes human-readable summary to dedicated file that Claude displays to user

**Implementation**:
```markdown
## Final Summary (Required)

At the end of your work:

1. Generate timestamped summary file: `SUMMARY-<agent-name>-<timestamp>.txt`
2. Write human-readable summary with key metrics
3. Output message to user with file path

Example output:
"Evaluation complete. Summary written to:
.agent_planning/SUMMARY-project-evaluator-2025-11-29-130418.txt

Key results:
- STATUS file: STATUS-2025-11-29-130400.md
- Completion: 75% (9/12 components)
- Critical gaps: 3 (auth system, API integration, test coverage)
- Recommendation: Implement P0 items from PLAN-2025-11-29-130415.md"
```

**Pros**:
- ✅ **Simple**: No MCP servers, no hooks, just file I/O
- ✅ **Durable**: Summary persists for later review
- ✅ **User-Controlled**: User can read immediately or later
- ✅ **Works within subagent context**: Subagents can write files
- ✅ **Discoverable**: Files in .agent_planning/ alongside STATUS/PLAN
- ✅ **No dependency on Claude Code features**: Works in any environment

**Cons**:
- ❌ Requires user to open file (not automatic display)
- ❌ Adds more files to .agent_planning/ directory
- ❌ Duplicates info (summary in hidden context + summary in file)

**Feasibility**: HIGH - Immediately implementable with Edit tool

### Solution 2: Echo to Console via Main Agent

**Approach**: Main agent (orchestrating command) explicitly asks each subagent to return summary, then echoes it to user

**Implementation**:
```markdown
<!-- In evaluate-and-plan.md -->

Step 1: Use the dev-loop:project-evaluator agent to evaluate the current status of the project.

Step 2: After project-evaluator completes, OUTPUT THE SUMMARY from project-evaluator directly to the user. Example:
"project-evaluator completed:
- STATUS file: STATUS-2025-11-29-130400.md
- Completion: 75% (9/12 components)
- Next: Running status-planner..."

Step 3: Use the dev-loop:status-planner agent to plan the remaining work...

Step 4: After status-planner completes, OUTPUT THE SUMMARY from status-planner directly to the user.

Step 5: Display combined summary of all work completed.
```

**Pros**:
- ✅ **Immediate visibility**: User sees summaries in conversation
- ✅ **No extra files**: Summaries display inline
- ✅ **Native to Claude Code**: Uses existing conversation UI
- ✅ **Progressive updates**: User sees each step complete

**Cons**:
- ❌ **Uncertain reliability**: Depends on whether subagent summaries are accessible to parent context
- ❌ **Command file bloat**: Adds explicit echo instructions to every command
- ❌ **Testing required**: Unknown if parent agent can reliably extract subagent summaries
- ❌ **Not durable**: Summaries lost when conversation ends

**Feasibility**: MEDIUM - Requires testing whether parent context receives subagent summaries in usable form

### Solution 3: Hook-Based Notification System

**Approach**: Configure hooks to detect agent completion and display summary

**Implementation**:
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "*agent*",
        "hooks": [
          {
            "type": "command",
            "command": "python3 \"${CLAUDE_PLUGIN_ROOT}\"/bin/display-agent-summary.py \"${TOOL_NAME}\""
          }
        ]
      }
    ]
  }
}
```

**Python script** (`bin/display-agent-summary.py`):
- Detects when agent completes (PostToolUse hook)
- Finds latest SUMMARY-* or STATUS-*/PLAN-* file in .agent_planning/
- Displays summary to console (stdout)
- Claude captures stdout and shows to user

**Pros**:
- ✅ **Automatic**: No manual file opening
- ✅ **Event-driven**: Triggers on agent completion
- ✅ **Reusable**: Works for all agents automatically

**Cons**:
- ❌ **Hook limitations**: PostToolUse may not fire for agent invocations (agents aren't tools)
- ❌ **Complex timing**: Hard to know when agent has fully completed
- ❌ **File detection heuristics**: Must guess which file contains summary
- ❌ **Stdout capture uncertain**: Unknown if hook stdout displays to user

**Feasibility**: LOW-MEDIUM - Hooks may not support agent lifecycle events

### Solution 4: MCP Server for Summary Aggregation

**Approach**: Build MCP server that logs agent summaries and provides query interface

**Implementation**:
1. Create MCP server: `dev-loop-monitor`
2. Agents call MCP tool: `mcp__dev-loop-monitor__log_summary`
3. MCP server stores summaries in structured format
4. User queries: `/query-summaries` → displays recent agent completions
5. Optional: MCP server pushes notifications to Claude when agent completes

**Pros**:
- ✅ **Queryable**: User can ask "what did the last evaluation find?"
- ✅ **Structured**: Summaries stored in searchable format
- ✅ **Historical**: Can review summaries from previous sessions
- ✅ **Real-time updates**: MCP can push notifications

**Cons**:
- ❌ **High complexity**: Requires Python MCP server implementation
- ❌ **External dependency**: MCP server must run alongside Claude
- ❌ **Not automatic**: User must query for summaries (unless push notifications work)
- ❌ **Overkill**: Heavy infrastructure for simple visibility problem

**Feasibility**: LOW - High implementation cost for marginal benefit over simpler solutions

## Architectural Concerns

### Why This Problem Exists

**Claude Code Design Philosophy**: Subagents use isolated context to:
- Preserve main agent context (prevent bloat)
- Enable parallel execution
- Allow focused work without main conversation noise

**Trade-off**: Isolation hides valuable information from users

**Our Solution**: Explicitly surface critical information while respecting isolation model

### Why File-Based + Echo Hybrid Works

1. **Files preserve subagent isolation**: Subagents write files (already doing this for STATUS/PLAN)
2. **Main agent echoes summaries**: Parent conversation displays key results (not full context)
3. **No architectural violations**: Uses existing tool capabilities (file I/O, message output)
4. **User-centric**: Optimizes for user experience without breaking Claude Code patterns
