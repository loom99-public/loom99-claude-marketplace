Summary (Minimal Control Loop Reframe)
======================================

Observations about LLM/Agent behavior
-------------------------------------

*   Rule adherence in long contexts is unstable unless rules are **re-anchored near the present** (restated/used immediately before work).
*   Large rule sets create **conflicting objectives**, causing drift, deferral, and “resurrection” of legacy systems to satisfy tests.
*   Large refactors/migrations stall at ~80–95% due to:
    *   remaining cross-cutting edge cases
    *   legacy dependents still reachable
    *   test suites encoding legacy implementation details
    *   outdated plans / target state ambiguity
    *   no forcing function for closure

Design goal
-----------

Use a **light-touch control loop** that:

*   keeps the agent aligned to a single target state,
*   prevents backward coupling and resurrection,
*   forces convergence on remaining blockers,
*   minimizes governance surface area and token overhead.

Minimal Control Loop (core mechanism)
-------------------------------------

A small set of **live artifacts** + a **repeatable ritual** that runs each phase:

### Live artifacts (kept short, updated continuously)

1.  `TARGET.md` — target end state + Definition of Done (one screen)
2.  `BOUNDARY.md` — single boundary rule + allowed bridge (one screen)
3.  `BLOCKERS.md` — exhaustive list of ship-stoppers / correctness-stoppers (one screen)
4.  `METRICS.md` — 2–4 monotonic measures of convergence (one screen)

### Ritual (performed at the start of each work phase)

*   Restate the current contents of the 4 artifacts.
*   Select exactly one highest-risk blocker.
*   Execute work until the blocker is eliminated or escalated with a concrete decision request.
*   Update artifacts and metrics.
*   Repeat.

Outcome
-------

This loop reduces agent failure modes without heavy governance:

*   prevents deferral by making “blockers” the only work queue
*   prevents resurrection via a single enforceable boundary/bridge
*   prevents drift via a compact, repeatedly re-anchored target state
*   enforces convergence via monotonic metrics and phase-based closure
