# Implementation Plan: Align do-more-now with dev-loop .agent_planning Directory Usage

**Generated**: 2025-12-16
**Topic**: Standardize .agent_planning directory structure across plugins

## Executive Summary

The `dev-loop` plugin uses topic-based subdirectories for organizing planning files (e.g., `.agent_planning/auth/`), while the `do-more-now` plugin uses a flat structure at the root `.agent_planning/` directory. This plan aligns `do-more-now` to match `dev-loop`'s topic directory pattern.

**User Decisions:**
- **Clean break**: Topic directories only, no backward compatibility for flat structure
- **Update /do:plan**: Add topic directory resolution like dev-loop
- **Add eval-cache**: Include evaluation caching feature

## Target State

### Directory Structure (Both Plugins)

```
.agent_planning/
├── <topic-slug>/                    # Topic-based subdirectories
│   ├── STATUS-<timestamp>.md        # Evaluation snapshots
│   ├── EVAL-<timestamp>.md          # Gap analysis (optional)
│   ├── PLAN-<timestamp>.md          # Full implementation plan
│   ├── DOD-<timestamp>.md           # Definition of Done (acceptance criteria only)
│   ├── WORK-EVALUATION-<timestamp>.md  # Implementation verification
│   ├── RESEARCH-<topic>-<timestamp>.md # Research findings
│   └── USER-RESPONSE-<timestamp>.md    # Plan approval record
├── eval-cache/                      # Reusable evaluation findings (shared)
│   ├── INDEX.md                     # Topic index with timestamps
│   ├── project-structure.md         # Project layout, key files
│   ├── test-infrastructure.md       # Test framework, patterns
│   ├── architecture.md              # Key patterns, data flow
│   └── runtime-<scope>.md           # Runtime behavior findings
└── do-command-logs/                 # Execution tracking (unchanged)
    ├── CURRENT_EXECUTION_ID.txt
    ├── CURRENT_SEQUENCE.txt
    └── partials/
```

### File: `plugins/do-more-now/commands/plan.md`

**Add after "Topic Resolution" section (~line 30):**

```markdown
---

## Step: Resolve Topic Directory

All planning files for a topic live in `.agent_planning/<topic-slug>/`.

**Process:**

1. Generate a slug from the topic (lowercase, hyphenated, short)
   - "user authentication" → `auth` or `user-auth`
   - "payment processing" → `payments`

2. List existing topic directories:
   ```bash
   ls -d .agent_planning/*/
   ```

3. Check for matches:

   **Exact match exists** → Use it, proceed to next step

   **Similar directories found** → Ask user:
   ```
   ┌─ Topic: "user authentication" ─────────────────────┐
   │                                                    │
   │ Similar existing topics found:                     │
   │ 1. auth/ (3 files, last modified: 2024-12-12)     │
   │ 2. login/ (1 file, last modified: 2024-12-10)     │
   │ 3. Create new: user-auth/                          │
   │                                                    │
   └────────────────────────────────────────────────────┘
   ```

   **No similar directories** → Create new directory:
   ```bash
   mkdir -p .agent_planning/<topic-slug>
   ```

**Output:** Topic directory path (e.g., `.agent_planning/auth/`)

---
```

## Evaluation Cache

Before evaluating, check the shared cache at `.agent_planning/eval-cache/`:

```bash
cat .agent_planning/eval-cache/INDEX.md 2>/dev/null
```

**Cache Freshness:**
- FRESH: < 1 hour - trust fully
- RECENT: < 24 hours - trust with verification
- STALE: > 24 hours - use as hints only
- ANCIENT: > 7 days - ignore

**After Evaluation:**
Update relevant cache entries in `.agent_planning/eval-cache/`:
- `project-structure.md` - if you learned about project layout
- `test-infrastructure.md` - if you learned about testing
- `architecture.md` - if you learned about architecture patterns
- `runtime-<scope>.md` - if you learned about runtime behavior
