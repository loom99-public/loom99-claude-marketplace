### P0: Design State Machine Definition

**P0.1: Create design lifecycle state machine spec**
- Location: `plugins/agent-control-loop/docs/_now/control-loop-system/6-design-state-machine.md`
- States: Proposed → InReview → Accepted → Active → Shipped → Superseded → Archived
- Terminal: Rejected
- Temporary: OnIce
- Map human gates (#1-5) to transitions

**Technical Notes:**
| From | To | Guard | Human Gate |
|------|-----|-------|------------|
| Proposed | InReview | PROPOSAL.md complete | No |
| InReview | Accepted | GOVERNANCE-DELTA.md present | Gate #1 |
| InReview | Rejected | Failure evidence | Gate #4 |
| Accepted | Active | In DESIGN_LINKS.md | No |
| Active | Shipped | Criteria satisfied | Gate #2 |
| Active/Shipped | Superseded | Replacement exists | Gate #3 |

### P1: Design Curator Agent + Skills

**P1.1: Create Design Curator agent**
- Location: `plugins/agent-control-loop/agents/design-curator.md`
- Model: sonnet
- Responsibilities:
  1. Keep /design/current coherent and minimal
  2. Ensure every design has explicit lifecycle state
  3. Maintain DESIGN_LINKS.md bridge to governance
  4. Prevent zombie docs
  5. Trigger human gates for approval transitions

**Behavioral Rules:**
1. Every design has state (no stateless docs)
2. Only current + active influence execution
3. Governance wins on conflict
4. State transitions require evidence
5. Forward links always (superseded → replacement)

**P1.2: Create design-state-validator skill**
- Location: `plugins/agent-control-loop/skills/design-state-validator/SKILL.md`
- Validates required artifacts per state
- Validates transition guards
- Returns specific validation failures

**P1.3: Create design-index-updater skill**
- Location: `plugins/agent-control-loop/skills/design-index-updater/SKILL.md`
- Scans /design/ for artifacts
- Updates /design/index.md
- Updates DESIGN_LINKS.md
- Moves terminal designs to archive

### P2: Consistency Auditor Agent + Skills

**P2.1: Create Consistency Auditor agent**
- Location: `plugins/agent-control-loop/agents/consistency-auditor.md`
- Model: haiku (fast analysis)
- Responsibilities:
  1. Check design/current vs governance/live for conflicts
  2. Check design/current vs repo reality for drift
  3. Classify conflicts (stale design / stale governance / unknown)
  4. Generate bounded resolution options
  5. Escalate major drift immediately

**Behavioral Rules:**
1. Three comparison axes (design-governance, design-reality, active-blockers)
2. Classify conflicts with root cause
3. Always 2-3 concrete options (not open-ended)
4. Non-destructive (read-only for analysis)
5. Tolerance thresholds (cosmetic→log, moderate→report, major→escalate)

**P2.2: Create consistency-checker skill**
- Location: `plugins/agent-control-loop/skills/consistency-checker/SKILL.md`
- Parses design/current binding surface
- Parses governance/live constraints
- Identifies contradictions
- Generates 2-3 resolution options per conflict

**P2.3: Create drift-detector skill**
- Location: `plugins/agent-control-loop/skills/drift-detector/SKILL.md`
- Infers architecture from repo
- Parses design/current claims
- Identifies drift deltas
- Classifies severity (cosmetic/moderate/major)

### P3: Core Commands

**P3.1: Create /loop:design command**
- Location: `plugins/agent-control-loop/commands/design.md`
- Subcommands:
  - `status` - Design plane summary
  - `validate` - Validate all designs
  - `promote <id>` - Trigger state transition
  - `sync` - Update indexes and DESIGN_LINKS

**P3.2: Create /loop:audit command**
- Location: `plugins/agent-control-loop/commands/audit.md`
- Subcommands:
  - `consistency` - Design vs governance
  - `drift` - Design vs reality
  - `full` - All checks

**P3.3: Create /loop:escalate command**
- Location: `plugins/agent-control-loop/commands/escalate.md`
- Subcommands:
  - `list` - Show pending gates
  - `<gate-id> <option>` - Resolve gate with decision

**The 5 Decision Gates:**
| Gate | Trigger | Transition |
|------|---------|------------|
| #1: Accept Proposal | Proposal ready | InReview → Accepted |
| #2: Declare Shipped | Implementation done | Active → Shipped |
| #3: Supersede Design | Conflict/replacement | Any → Superseded |
| #4: Reject Proposal | Evidence fails | InReview → Rejected |
| #5: Change Boundary | Cross-world coupling | BOUNDARY.md update |
